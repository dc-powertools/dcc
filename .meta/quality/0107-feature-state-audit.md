## Important boundaries

1. Codex filesystem inspection confirmed packages/standalone contains the installed
   executable; earlier runtime use additionally populated packages/app-server-daemon.
   Both are package contents even though daemon package was first installed at
   runtime. An image-owned policy needs to accommodate daemon bootstrapping and
   updates in ephemeral writable container storage, or provision that package in the
   image. A mount split alone does not prove no runtime downloads will occur.
2. Codex tmp/, app-server-control/ and app-server-daemon/ (without packages prefix)
   include runtime scratch, sockets, PID files and locks. These should generally be
   ephemeral, not durable and not image-seeded. Distinguish daemon runtime directory
   from packages/app-server-daemon. Runtime logs may be persisted separately.
3. ~/.cargo/bin can mix image-installed rustup proxies with user cargo-install tools.
   Cannot classify every file by directory alone if runtime-installed tools are to
   persist. User's requested policy resolves this by keeping executable installs
   ephemeral unless rebuilt into the image; an alternative needs a separate install
   root, with matching Cargo install bookkeeping kept together.
4. Claude installer writes ~/.claude/settings.json and backup/config material too;
   those are configuration defaults, not binary payload. Existing mutable state must
   not be unconditionally overwritten just because installer wrote a default.
   Existing image also contains ~/.claude.json outside the declared durable root;
   auth/config coverage there needs verification before claiming full persistence.
5. Plugin/skill installations selected by a user are user state despite containing
   code. Automatically generated built-in skills and runtime caches need separate
   handling; exact per-tool runtime whitelists cannot be derived from these Feature
   installers alone. Mo runtime internals were not executed or exhaustively audited.
6. Keeping executable trees image-controlled means leaving them in image/container
   storage, not automatically making them read-only. In-container updates can remain
   ephemeral as requested. Updates/daemon compatibility need verification if paths
   are relocated. CODEX_INSTALL_DIR only relocates launcher; CODEX_HOME determines
   package root. Excluding packages requires nested image storage, selected persistent
   mounts, or a supported separation of install root and state root. Cargo can likewise
   benefit from a dedicated image tool-install prefix rather than overlapping mounts.
7. No hash is needed to decide ownership when declared explicitly. Persistent
   directories should be preserved without image reconciliation. Image-provided user
   defaults (AWS config, Claude defaults) require explicit initialize-if-absent or
   config policy; that is separate from preserving mutable state or installing tools.
